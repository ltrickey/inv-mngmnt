# Changelog: Private S3 Bucket with Signed URLs

## Summary

Updated S3 bucket configuration to be **completely private** with images only accessible through time-limited signed URLs generated by the Flask application. This prevents direct access to images and ensures all image requests go through your application.

## Security Improvement

### Before (Public S3)
```
Anyone with URL → S3 Bucket → Image (public)
https://bucket.s3.amazonaws.com/images/photo.jpg ❌ Accessible by anyone
```

### After (Private S3 with Signed URLs)
```
User → Flask App → Generates Signed URL → S3 Bucket → Image
https://bucket.s3.amazonaws.com/images/photo.jpg?signature=xyz... ✅ Only valid for 1 hour
```

## Changes Made

### 1. Infrastructure (`infrastructure/s3.tf`)

**Block all public access:**
```hcl
# Before
block_public_policy     = false  # Allow public bucket policies
restrict_public_buckets = false  # Allow public bucket access

# After
block_public_policy     = true   # Block ALL public bucket policies
restrict_public_buckets = true   # Restrict ALL public bucket access
```

**Bucket policy - EC2 only access:**
```hcl
# Before: Public read access for everyone
Principal = "*"

# After: Only EC2 instances with LabRole can access
Principal = {
  AWS = data.aws_iam_role.ec2_role.arn
}
```

### 2. Flask Application (`server/app.py`)

**Changed from direct URLs to signed URLs:**

```python
# Before: Direct S3 URLs (public)
S3_BUCKET_URL = os.environ.get('S3_BUCKET_URL')
return f"{S3_BUCKET_URL}/images/photo.jpg"

# After: Signed URLs (private, expires in 1 hour)
S3_BUCKET_NAME = os.environ.get('S3_BUCKET_NAME')
signed_url = s3_client.generate_presigned_url(
    'get_object',
    Params={'Bucket': S3_BUCKET_NAME, 'Key': s3_path},
    ExpiresIn=3600  # 1 hour
)
return signed_url
```

### 3. Deployment Scripts

**Updated environment variables:**
- `S3_BUCKET_URL` → `S3_BUCKET_NAME`
- Added `S3_BUCKET_REGION`

### 4. Outputs (`infrastructure/outputs.tf`)

```hcl
# Removed: s3_bucket_url (no longer applicable)
# Added: s3_bucket_region (needed for signed URLs)
```

## How It Works

### Image Request Flow

1. **Browser requests product data** from Flask
2. **Flask queries DynamoDB** for product (contains image path like `infrastructure/images/photo.jpg`)
3. **Flask calls `get_image_url()`** to transform path
4. **Flask uses boto3** to generate signed URL:
   ```python
   s3_client.generate_presigned_url(
       'get_object',
       Params={'Bucket': 'bucket-name', 'Key': 'images/photo.jpg'},
       ExpiresIn=3600  # Valid for 1 hour
   )
   ```
5. **Returns signed URL** like: `https://bucket.s3.amazonaws.com/images/photo.jpg?X-Amz-Algorithm=...&X-Amz-Expires=3600&...`
6. **Browser uses signed URL** to load image directly from S3
7. **URL expires after 1 hour** - new requests get new signed URLs

### Security Benefits

✅ **Private Bucket** - Direct access blocked  
✅ **Time-Limited** - URLs expire after 1 hour  
✅ **Application-Controlled** - Only Flask can generate URLs  
✅ **Audit Trail** - All access goes through Flask (can be logged)  
✅ **No Hot-Linking** - Can't embed images on other sites permanently  

## IAM Requirements

The EC2 IAM role (LabRole) needs these S3 permissions:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::bucket-name",
        "arn:aws:s3:::bucket-name/*"
      ]
    }
  ]
}
```

**Note:** AWS Academy's `LabRole` already has these permissions by default.

```bash

# Try direct access (should be denied)
curl -I https://$S3_BUCKET.s3.us-east-1.amazonaws.com/images/placeholder.png

```

### Test via Flask (Should Work)

```bash
# Access product with image
curl http://your-ec2:8000/products | jq '.[0].image_url'
# Expected: Signed URL with query parameters ✓

# Use the signed URL
curl -I "$(curl -s http://your-ec2:8000/products | jq -r '.[0].image_url')"
# Expected: 200 OK ✓
```

### Verify Signed URL Structure

A valid signed URL looks like:
```
https://bucket.s3.region.amazonaws.com/images/photo.jpg?
  X-Amz-Algorithm=AWS4-HMAC-SHA256&
  X-Amz-Credential=...&
  X-Amz-Date=20260212T120000Z&
  X-Amz-Expires=3600&
  X-Amz-Signature=...&
  X-Amz-SignedHeaders=host
```

## Expiration Time

URLs expire after **1 hour** by default. To change:

```python
# In server/app.py, line ~95
signed_url = s3_client.generate_presigned_url(
    'get_object',
    Params={'Bucket': S3_BUCKET_NAME, 'Key': s3_path},
    ExpiresIn=3600  # Change this value (in seconds)
)
```

**Recommendations:**
- **1 hour (3600)**: Default - good balance
- **15 minutes (900)**: More secure, but users might see expired links
- **24 hours (86400)**: Less secure, but better for caching

## Fallback Behavior

If signed URL generation fails:

```python
except Exception as e:
    logger.error(f"Failed to generate signed URL: {e}")
    return "/images/placeholder.png"  # Fallback to Flask-served placeholder
```

The app gracefully falls back to serving a placeholder image from Flask.

## Performance Considerations

### Signed URL Generation

- **Fast**: ~1-2ms per URL generation
- **No S3 API call**: URLs generated locally using IAM credentials
- **Cached in response**: Browser caches the signed URL until expiration

### Recommendation

For high-traffic sites, consider:
1. Caching signed URLs in Redis for their expiration period
2. Generating batch signed URLs upfront
3. Using CloudFront with signed cookies instead

## Troubleshooting

### Images Not Loading

**Check Flask logs:**
```bash
ssh ec2-user@instance
sudo journalctl -u product_catalogue_flask -n 50
# Look for "Failed to generate signed URL" errors
```

**Check IAM permissions:**
```bash
# From EC2 instance
aws s3 ls s3://bucket-name/images/
# Should list images (proves IAM role has access)
```

### 403 Forbidden on Images

- ✅ **Expected** if accessing S3 directly
- ❌ **Problem** if accessing via signed URL from Flask

**Solution:** Ensure Flask has boto3 installed and IAM role is attached to EC2.

## Comparison: Public vs Private

| Feature | Public Bucket | Private Bucket (Signed URLs) |
|---------|---------------|------------------------------|
| Direct access | ✅ Anyone | ❌ No one |
| Via Flask | ✅ Yes | ✅ Yes |
| Hot-linking | ❌ Possible | ✅ Prevented |
| URL expiration | ❌ Never | ✅ 1 hour |
| Audit trail | ❌ No | ✅ Yes (via Flask) |
| Browser caching | ✅ Yes | ✅ Yes (until expiration) |
| Performance | ⚡ Direct | ⚡ Direct (after URL generated) |
